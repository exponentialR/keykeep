# Security policy

Keykeep is an experimental beta. It has not received an independent security audit. Use fictional credentials when evaluating the public demo. An implementing-agent review and automated checks do not establish suitability for critical credentials.

## Report privately

Use [GitHub's private vulnerability reporting form](https://github.com/exponentialR/keykeep/security/advisories/new). Include the affected commit/version, a minimal reproduction with synthetic data, expected behaviour and impact. Never include a real vault, master password, email code or API key.

If private reporting is unavailable, open an issue asking for a private reporting channel without describing the vulnerability. Do not publish exploitation details in a public issue or pull request.

We will investigate reports and agree disclosure with the reporter. No paid bug-bounty programme or guaranteed response time is offered.

## Supported versions

The latest beta on `main` receives fixes. There is no stable 1.0 release yet. Check the [release plan](RELEASE_PLAN.md) and [threat model](docs/THREAT_MODEL.md) for known limits and review gates.
